## D006 — Source of daily completeness for OpenAQ · 2026-11-03 · DECIDED (student approved recommended set)
- **Proposal:** Use OpenAQ `/v3/sensors/{id}/days` aggregates (one request per sensor-year) and the `coverage.observedCount` field as "hours observed" for the audit only. Days are 01:00–00:00 local time per OpenAQ docs.
- **Alternative:** `/hours` endpoint (~9× more requests). Will be used in Stage 2 for the actual PM2.5 values; Stage 1 will spot-check a few sensors to confirm `observedCount` equals the number of hourly values.
- **Update 2026-11-03:** The spot-check matched exactly for 2025-type data (124 of 124 sensor-days). But pre-2025 CPCB data in OpenAQ has two overlapping hourly records per clock hour (:00 and :30 IST), so `observedCount` reaches 48. Fix: sensor-years with any day above 24 records have their counts halved (`estimate_hours`). This is an approximation, used for the screening audit only.

- **Options:** Kerala only (rejected: 6 usable stations, below the 15 set in `configs/audit.yaml`) / five states (chosen).

## D011 — Study period (was P6)
- **Decision:** 2021-01-01 to 2025-12-31.
- **Options (usable stations ≥ 70 %, all / Kerala):** 2021–2024 40 / 6; **2021–2025 42 / 6**; 2022–2025 43 / 5; 2023–2025 54 / 3.
- **Reason:** 2025 is the best-covered year (65 usable stations, Kerala 5) while 2024 has only 3 usable Kerala stations; five SW-monsoon seasons per Kerala station. Caveat: CPCB may still revise 2025 data; the files used are hashed in the manifest.

## D012 — Valid day (was P1)
- **Decision:** At least 18 of 24 hourly PM2.5 values.
- **Options:** 16 / **18** / 20. Stage 3 will report how many monsoon days each option keeps.

## D013 — Usable-station threshold (was P2)
- **Decision:** Headline results use stations with ≥ 70 % valid days over the study period (42 stations). A sensitivity analysis uses ≥ 50 % (56 stations). Within either set, every valid day is used.
- **Reason:** 70 % is easier to defend; the 50 % set tests whether extra (sparser) stations help spatial generalisation, e.g. in Andhra Pradesh (4 → 6 stations).

## D014 — Seasons (was P3)
- **Decision:** IMD four seasons: winter (Jan–Feb), pre-monsoon (Mar–May), SW monsoon (Jun–Sep), NE monsoon / post-monsoon (Oct–Dec).
- **Options:** IMD (chosen) / project labels with Dec–Feb as "post-monsoon" (rejected: non-standard, and Dec–Feb is the dry winter).

## D015 — Duplicate rule, CPCB vs OpenAQ (was P4)
- **Decision:** A CPCB station and an OpenAQ location are the same site if their normalised names match or they are within 500 m. Keep CPCB, drop the OpenAQ copy. OpenAQ is used only for reference monitors absent from CPCB; low-cost sensors are excluded from the target.
- **Rejected:** correlation rule r ≥ 0.95 (same monitors give median r 0.91, `cpcb_vs_openaq_agreement.csv`).

## D016 — Target grid (was P8)
- **Decision:** 1 km daily grid (MAIAC AOD native resolution). Coarser inputs (TROPOMI, ERA5) are resampled to it; station-level extraction windows (e.g. 5 km, 10 km) are tested in Stage 4.
- **Options:** **1 km** / 0.1° (rejected: several stations in Hyderabad, Bengaluru and Chennai would share cells).

## D017 — Coordinates for stations not located via OpenAQ (was P9)
- **Decision:** Take coordinates from CPCB's official station list document; state pollution control boards as fallback. Every coordinate added by hand records its source in the station table.
- **Affected (usable over 2021–2025):** Anand Kala Kshetram (Rajamahendravaram), ICRISAT Patancheru, Sanathnagar, Toll Gate (Tirumala).
- **Result 2026-11-03:** CPCB's "CAAQMS Stations List All India" PDF (`data/raw/cpcb/station_list/caaqm_stations_all_india_20261103.pdf`) lists names and cities only, with no coordinates. The coordinates were instead read from CPCB's own All India AQI Dashboard, where the station map centres on the selected station. They are stored in `configs/station_coordinates_manual.csv` with source and date, and applied by `src/ingest/cpcb_stations.py` only where no OpenAQ match exists.
- **Check:** for ICRISAT and Sanathnagar the dashboard coordinates equal one of the conflicting OpenAQ entries exactly, which identifies the others (OpenAQ 7583, 26.7 km off; 2594, 5.7 km off) as wrong. For Bollaram, which was not changed, the dashboard and OpenAQ differ by 3.6 km. Toll Gate (Tirumala) is stored with 2 decimals only (about 1 km precision). All 42 headline and 56 sensitivity stations now have coordinates.

## D019 — Reanalysis aerosol product (S1)
- **Decision:** MERRA-2 aerosol diagnostics, Earth Engine `NASA/GSFC/MERRA/aer/2` (hourly, ~0.5° × 0.625°). Surface PM2.5 is reconstructed from the species bands (formula and citation recorded in `docs/data_dictionary.md` once verified); total AOD from `TOTEXTTAU`.

## D021 — Stations to extract (S3)

## D022 — Satellite sampling (S4)
- **Decision:** For TROPOMI and MAIAC, store the centre-pixel value and the 5 km and 10 km buffer means, each with its valid-pixel count and the QA/cloud rule used. Buffer choice is made in Stage 4.

## D023 — Time window and time handling (S5)
- **Decision:** Extract 2020-12-01 to 2025-12-31 (December 2020 provides the 1–3 day lags for 1 January 2021). Hourly products are extracted in UTC and aggregated locally, so both a daily IST mean and a 12:00–15:00 IST overpass-window value can be built in Stage 4.

## D024 — CPCB timestamp convention (S6)
- **Decision:** Settle empirically by aligning CPCB hourly values with OpenAQ hourly values (which carry explicit UTC start/end times) for the same monitors. Result recorded below when known.
- **Result 2026-11-03:** CPCB labels are **IST hour-start** times: the hour labelled `HH:00` covers HH:00–HH+1:00 IST, i.e. UTC start = label − 5:30. Evidence (`reports/tables/cpcb_timestamp_check.csv`, `src/audit/cpcb_timestamp_check.py`): for 5 stations (one per state) and two weeks of 2025 (March, July), the offset k = 0 gives the highest correlation at every station (median r 0.986 vs 0.944 at k = −1 and 0.878 at k = +1). Median absolute difference at k = 0 is 0.75 µg/m³, so OpenAQ is not a byte-identical copy, but the alignment is unambiguous.

## D027 — TROPOMI product level · 2026-11-03 · DECIDED (student: "Approve, keep L3")
- **Finding:** The Earth Engine S5P "L3" products are pre-filtered by Google (qa_value thresholds: NO2 0.75, AER_AI 0.8, CO/HCHO/CLOUD 0.5, SO2 > 0.5 plus extra criteria) and contain no `qa_value` band. Stage 4 can therefore only make the filter *stricter* (e.g. with `cloud_fraction`), not test looser QA thresholds.
- **Decision:** Use the Earth Engine L3 products (already extracted), state the fixed pre-filter in the thesis as a limitation, and test cloud-fraction thresholds in Stage 4.
- **Alternative:** Download L2 orbit files from the Copernicus Data Space Ecosystem (with `qa_value`) and grid them ourselves: full QA control, but tens of GB per year and a separate pipeline.

## D028 — PM2.5 QC rules (brief, Stage 4 task 1)
- **Decision:** S3a = remove negative, zero and exactly-1000 values; remove flat-line runs ≥ 24 h; remove isolated spikes (1–2 h runs > 4 × centred 25 h median and > 100 µg/m³). Sensitivity: flat-line ≥ 12 h (S2b).
- **Effect (valid days kept):** all 113,726 of 114,258 (−532, −0.47 %); Kerala Jun–Sep 3,306 of 3,315 (−9).
- **Options:** S1 (invalid only, −2 days) / S2a–S2c (flat ≥ 24 / 12 / 6 h: −418 / −851 / −1,644) / **S3a** / S3b (all spikes, −599).

## D029 — MAIAC QA (task 2)
- **Decision:** "clear" (cloud mask = clear) as the main AOD; "best" as sensitivity.
- **Effect (Kerala Jun–Sep, valid days with AOD in 10 km):** clear 36.9 %, best 25.1 %. "Any" equals "clear" (MAIAC retrieves only clear pixels).

## D030 — TROPOMI cloud filter (task 2; L3 pre-filter fixed by D027)
- **Decision:** No extra cloud filter; keep `cloud_fraction` (and NO2-product cloud fraction) as features. Sensitivity: drop station-days with 10 km mean cloud fraction > 0.3.
- **Effect (Kerala Jun–Sep, NO2 in 10 km):** none 56.1 %; ≤ 0.5 55.2 %; ≤ 0.3 50.3 %; ≤ 0.2 40.2 %. The qa ≥ 0.75 pre-filter already removes most cloudy NO2 pixels: at the station pixel the filter changes almost nothing (37.9 % → 37.0 % at ≤ 0.2).
- **Note:** this is a day-level filter on the buffer mean; a per-pixel filter needs re-extraction.

## D031 — Minimum valid pixels in a buffer (task 4)
- **Decision:** No hard minimum; store the valid-pixel count as a feature (as the brief asks) and test ≥ 10 % / ≥ 25 % in Stage 5.
- **Effect (Kerala Jun–Sep, AOD clear in 10 km):** any 36.9 %; ≥ 10 % 22.4 %; ≥ 25 % 15.4 %; ≥ 50 % 8.7 %. A minimum removes monsoon days first, which is the regime the thesis studies.

## Stage 4 proposals, part 2 · 2026-11-04 · PROPOSED (waiting for student)
Numbers: `reports/tables/target_comparison.csv`, `reports/tables/buffer_coverage.csv`.

## D034 — Overpass-window target
- **Proposal:** Mean of QC-passed hours starting 12:00, 13:00, 14:00 IST; valid with ≥ 2 of 3 hours. Window confirmed from Earth Engine overpass times over Kochi and Hyderabad: TROPOMI 12:09–14:11 IST, MAIAC Aqua 13:15–15:00 IST (Terra 10:15–11:15 is outside).
- **Effect:** 124,342 valid overpass station-days vs 113,727 valid daily (2021–2025). Requiring 3 of 3 hours is the stricter alternative.

## D035 — Satellite buffer for model features
- **Proposal:** 10 km buffer (b10) as the main Tier A input; station pixel and 5 km as sensitivity runs in Stage 5.
- **Evidence (valid daily-target days with a value / Spearman ρ with PM2.5):** NO2 pt 52.9 % / 0.32, b5 63.4 % / 0.34, b10 68.9 % / 0.35; AOD pt 32.4 % / 0.22, b5 48.5 % / 0.24, b10 55.0 % / 0.25. Exception: in the SW monsoon AOD ρ falls with buffer size (pt 0.23, b10 0.16), so the trade-off is reported per season.

## D036 — Primary target
- **Proposal:** Daily mean (24 h, IST) as the primary target (policy-relevant: India's PM2.5 standard is a 24 h mean); overpass-window target as the secondary, satellite-matched comparison. Both are in the dataset.
- **Evidence:** the two agree closely (Spearman ρ 0.88; overpass/daily median ratio 0.96, 0.90 in winter).

## D037 — PM2.5 lag features
- **Proposal:** Keep PM2.5 lags 1–3 in Tier A and B (brief, task 6), and add a "no PM2.5 lags" variant of each tier in Stage 5. Reason: lags exist only where a monitor exists, so a model meant for unmonitored locations (mapping, leave-one-station-out) must be evaluated without them, otherwise spatial skill is overstated.
